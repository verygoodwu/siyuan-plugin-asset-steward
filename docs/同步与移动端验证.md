# v1.1.0 验证与开发

本次合并桌面同步闪烁修复和手机端初版，不修改账本数据结构。手机端提供快速记账、基础总览和只读流水搜索；账户编辑、规划和完整报表仍在桌面端完成。

## 可复现命令

需要 Node.js 24 与已安装的 Chrome/Chromium。

```sh
npm ci
npm test
npm run build
npm run test:browser
npm run test:mobile
npm run package
```

Windows默认使用标准路径下的Chrome；其他安装路径可通过TEST_CHROME指定。Linux/macOS需设置TEST_CHROME为已安装浏览器的绝对路径。浏览器测试只连接隔离的内存模拟API，不读取或改写真实账本。

## 验证内容

- 状态层12项：相同内容跳过保存、属性顺序无关、真实修改、更新就地应用、草稿延期、常见并发冲突、读取异常与删除保护、初始化失败、写入失败重试、保存期间继续修改、首次创建和远端已有相同内容。
- 桌面9组：100次通知不重建表单、不写盘；调整宽度保留规划输入；草稿及冲突保护；明确加载同步版本；新增只写一次；页签/滚动保持；重开和读取失败保护。
- 手机12组：入口注册、320/390/430像素布局、账户及输入保留、支出与收入余额联动、重复提交防护、每日快照、基础总览、流水搜索、100次同步与草稿保留、手动加载、失败重试、移动浏览器识别、无账户及初始化异常保护。

Windows思源3.8.2曾安装同步修复版并校验运行文件。实机190秒观察未发现内容或写入时间变化，但当时没有新跨设备通知；跨设备行为主要通过隔离通知测试验证。iOS/Android实体设备与系统软键盘未验证。

## 数据边界

同步通过onDataChanged处理；已有视图引用同一个AppState对象。检测到未提交输入时不应用远端数据，不强制重建界面；加载同步版本需要用户明确确认。

保存前读取远端并核对基线，成功后回读验证。思源文件API不提供原子条件写入，本次不承诺两个设备完全同时写入时的事务合并。

本地备份和实机报告目录不进入源码提交或安装包。
